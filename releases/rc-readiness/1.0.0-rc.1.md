## Review findings

PR #71 has received nine material P1 review findings during preparation:

1. The initial path comparison was circular because it only proved that candidate-listed paths existed. Remediation added an immutable `v0.10.0` path/contract checkpoint plus a negative stable-path-removal regression.
2. The initial tool compatibility coverage checked paths and catalog strings but did not exercise semantic behavior. Remediation added an immutable published tool-behavior checkpoint, command/result contract and schema verification, CLI option checks, exit-code exercises, and real dry-run/overwrite behavior validation.
3. The original readiness record marked permanent validation `Passed` using a run on a tree that predated the readiness record and later documentation commits. The record now keeps exact record/document tree validation `NotRun` until a subsequent exact-head CI run completes.
4. `MANIFEST.md` and `ROADMAP.md` retained an older functional-candidate SHA after tool-behavior remediation. Top-level documents now delegate exact functional-candidate/run traceability to this readiness record instead of duplicating a moving SHA.
5. Stable identifier claims were prose-only. Remediation extends the published checkpoint with governance/profile front-matter IDs and schema/tool-result `$id` values, enumerates the C# identifiers promoted stable in this RC, and adds mutation/removal negative tests.
6. Normative rule IDs and meaning were initially enforced only for governance and C#. Remediation first established rule-contract enforcement and was then broadened to protect every published numbered normative-rule surface across all repository package families through immutable `v0.10.0` trees or explicit changed-source contracts; representative non-governance coverage includes `SEC-INPUT-001`.
7. The initial normative-rule remediation still omitted published rules outside governance and C#. The final rule checkpoint now covers the complete published numbered-rule surface and includes a global candidate rule scan that rejects any rule-bearing file outside an anchored tree or explicit changed-source contract.
8. Public tool finding-code values and meanings were not pinned. Remediation adds `0.10.0-finding-codes.json`, protects unchanged published tool source trees, explicitly inventories codes in changed stable tool sources, and exercises representative emitted findings.
9. `releases/README.md` overstated the RC as permanently validated even though the source readiness record intentionally keeps exact record/document tree validation `NotRun`. The release index now distinguishes validated functional evidence from the exact source-record tree and requires exact-head CI in PR metadata after record/document updates.
