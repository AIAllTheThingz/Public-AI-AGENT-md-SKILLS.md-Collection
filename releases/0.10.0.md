# Public-Access-Agents 0.10.0

## Publication state

- Repository maturity: pre-1.0
- Compatibility class: pre-1.0 minor release with explicitly documented breaking changes
- Intended tag: `v0.10.0`
- Status: **Prepared, not published**
- Git tag: **Not created**
- GitHub Release: **Not created**
- License: Apache-2.0

This document prepares the first forward-only publication after the unpublished `0.9.0` baseline. It does not authorize or imply that `v0.10.0` exists.

Publication requires a dedicated final preparation step that moves the canonical repository `VERSION` to `0.10.0`, finalizes the dated changelog entry, validates the exact source commit, builds deterministic artifacts, receives any required review, and only then creates the tag.

The current repository state also enforces the historical boundary in code: `releases/release-state.json` marks `0.9.0` as prepared/unpublished, release tag validation rejects that version, and the builder refuses to construct publication artifacts for it.

## Breaking changes

- Repository-maintenance approval behavior changes relative to the prepared `0.9.0` governance contract: low- and moderate-risk routine repository changes may be maintainer self-reviewed after permanent CI when no independent-review gate applies. Independent review remains mandatory for high/critical risk, breaking repository changes, the final `1.0.0` compatibility approval, stable-maturity commitments, and explicit exception gates.
- Canonical schema and tool-result `$id` values move from raw GitHub URLs under the former `AIAllTheThingz/Public-Access-Agents` repository path to `AIAllTheThingz/Public-AI-Governance`. Schema structure, required fields, property types, and instance validation behavior are unchanged, but consumers that persist or compare exact `$id` strings must migrate those identifiers.

The repository-maintenance item does not weaken adopter-facing engineering, security, testing, validation, or completion-evidence standards. The machine-readable identifier migration is explicitly classified as breaking under the repository release policy and is covered by the migration guidance below.

## Tooling changes

- Hardened validation and release workflows with immutable GitHub Action pins, Ubuntu 24.04 hosted-runner boundaries, Python 3.13, and SHA-256 hash-locked validation dependencies.
- Split release validation/build from publication so write permission is held only by the publication job.
- Added a machine-readable publication-state boundary that records prepared/unpublished versions; release validation now emits `RELEASE_PUBLICATION_BLOCKED` and artifact construction fails closed for those versions before the publish job can run.
- Added negative regression coverage that executes both the forbidden `v0.9.0` tag-validation path and the artifact builder, verifies no blocked artifacts are produced, and confirms workflow validation precedes build/publication.
- Added Dependabot maintenance for GitHub Actions and direct Python validation dependencies.
- Updated `validate-tools` to structurally parse workflow YAML, validate immutable action and Docker references, inspect effective static matrix runners, follow referenced local composite actions, verify repository-root containment, and enforce bidirectional direct-dependency/hash-lock synchronization.
- Required every resolved lock dependency to include a valid SHA-256 hash.
- Added regression coverage for workflow syntax, action pinning, matrix behavior, dependency-lock drift, missing dependencies, local composite actions, repository path containment, runner labels, and package-name canonicalization.
- Updated `validate-schemas`, `generate-manifest`, and `compose-agents` package behavior and metadata for the new schema/package boundaries.
- Added permanent read-only skill validation and integrated it into the complete validation pipeline.
- Updated canonical machine-readable schema/tool-result identifiers from the former repository path to `AIAllTheThingz/Public-AI-Governance`.

## Security

- Reduced workflow supply-chain mutability through immutable action references and hash-locked Python dependencies.
- Reduced release-token exposure by separating validation/build from publication permissions.
- Added a fail-closed executable guard so a tag for a version recorded as prepared/unpublished cannot advance through validation/build to `gh release create`.
- Added workflow checks for floating action refs, mutable Docker action references, floating GitHub-hosted runner aliases, invalid workflow YAML, local composite dependency escapes, and validation dependency-lock drift.
- Added C#, PowerCLI, virtualization, operating-system, and networking safeguards for their respective trust, control-plane, lifecycle, execution, and recovery boundaries.
- Kept release publication tag-driven and intentionally unexecuted during this preparation work.

## Known limitations

- `v0.10.0` has not been created and no `0.10.0` GitHub Release exists.
- `VERSION` remains on the prepared `0.9.0` baseline until a dedicated final publication-preparation change deliberately advances it to `0.10.0`.
- Release publication remains `NotRun` until the exact final source commit is reviewed, validated, tagged, and published.
- Immutable references reduce mutation risk but do not prove third-party provenance or vulnerability-free dependencies.
- Most standards packages remain at `baseline`, not `stable`.
- The repository currently has one active maintainer.
- Package-level integration with live infrastructure and vendor control planes remains environment-dependent and is not established by repository validation.

## Pre-publication validation

Before creating `v0.10.0`, the final release-preparation commit must set `VERSION` to `0.10.0`, finalize the changelog entry, and then run from the exact candidate source commit:

```bash
python -m pip install --require-hashes -r tools/validate-schemas/requirements.lock
python tools/validate-all/run_all.py --include-tests
python tools/release/validate_release.py --tag v0.10.0
python tools/release/build_release.py --tag v0.10.0 --output-dir dist --force
```

Verify:

```bash
cd dist
sha256sum -c SHA256SUMS.txt
```

Tag creation and GitHub Release publication must remain separate from preparation until those checks and required reviews are complete.
