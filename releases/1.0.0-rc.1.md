# Public-Access-Agents 1.0.0-rc.1

Release candidate for the repository's first stable compatibility contract. This candidate exercises the `1.0.0` compatibility gate, includes the breaking migrations below relative to published `v0.10.0`, and does not claim that final `1.0.0` is ready or published.

## Breaking changes

- Strengthens the existing Site Reliability Engineering and Testing and Quality Engineering package contracts with mandatory production-readiness, scaling-strategy, and contextual performance-test decisions and evidence. An overall scaling strategy may be `Verified` only after every applicable area is `Verified`; performance-test execution state is separate from outcome and a validated claim requires every applicable test type to have a current explicit `Pass`; unresolved, failed, not-run, or blocked evidence prevents those claims. Existing adopters of either package must migrate their tailored instructions, templates, and evidence records before claiming conformance.
- Adds Product Management and User Experience as conditional overlays to all 13 canonical project profiles. Profile selection alone does not select either package, but each overlay becomes mandatory when its documented product or human-experience predicate is satisfied. Existing profile adopters whose scopes satisfy a predicate must migrate.

## Normative changes

- Promotes the C# language package from `baseline` to `stable` using the evidence-backed maturity decision completed under issue #42.
- Defines the intended `1.0.0` compatibility surface for stable repository paths, identifiers, schemas, templates, executable tool contracts, release artifacts, and the C# stable package boundary.
- Explicitly excludes all packages not enumerated as stable from the stable package promise, even when their repository paths remain subject to ordinary compatibility and migration policy.
- Adds complete baseline Product Management and User Experience discipline packages with evidence-backed requirements, acceptance, traceability, explicit performed and non-run research states, journey, usability, validation, and accessibility-boundary controls.
- Integrates Product Management and User Experience as conditional profile overlays, with representative examples promoting or omitting them based on scoped product and human-interaction concerns.
- Adds an explicitly selected Product Inception Lifecycle with stable normative rule IDs for its Concept, Requirements, Design, Build, prototype, production-candidate, traceability, exception, and evidence-backed product-lifecycle controls distinct from component maturity. Lifecycle evidence states are closed; the Build Gate requires Product Management traceability plus every other applicable package selection or justified omission; `production-candidate` requires every material requirement implemented, every applicable functional and nonfunctional acceptance criterion at a current explicit `Pass`, and the selected SRE package's complete readiness contract; `production` retains that boundary plus accountable approval; and `scaled-production` requires the selected SRE package's complete scaling contract.
- Adds authoritative standards-body and first-party starting points for requirements engineering, UX, reliability, scaling, non-C# language packages, and Rust unsafe-code boundaries without asserting compliance or certification.

## Editorial changes

- Adds a durable release-candidate compatibility inventory and RC readiness evidence.
- Reconciles release documentation with the forward-only `1.0.0-rc.1` candidate state.

## Tooling changes

- Adds permanent regression coverage for the RC compatibility inventory, migration boundary, stable-path existence, package-maturity scope, and release-state invariants.
- Updates `compose-agents` to validate `AIAllTheThingz.governanceSelections` paths, include selected governance sources in copied bundles, composition manifests, and generated indexes, and retain the selected lifecycle's declared Exception Process dependency.
- Exercises the existing prerelease-aware release validator rather than introducing a parallel RC release mechanism.

## Deprecations

None.

## Migration notes

See [`migrations/1.0.0-rc.1.md`](migrations/1.0.0-rc.1.md).

The candidate is breaking for existing SRE and Testing adopters and for existing canonical-profile adopters whose scope satisfies a new Product Management or User Experience predicate. Adopters intentionally evaluating the RC must update their pinned repository source, complete the applicable versioned migration steps, rerun validation, and review the newly explicit C# stable commitment and baseline-package exclusions.

## Security

- No new privileged runtime, network access, secret handling, or production execution is introduced by the compatibility gate.
- The RC inventory preserves existing security/governance authority and makes package-boundary overclaims fail-visible.
- Existing schema, template, tool, package-adoption, path-containment, and release validation remain part of permanent CI.

## Known limitations

- This source candidate is not itself proof of a published `v1.0.0-rc.1` Git tag or GitHub Release.
- The breaking package and profile changes require qualified independent specialist review on the exact final release head before merge, tagging, or publication; automated review and earlier approvals do not satisfy that gate.
- Final `1.0.0` remains blocked until at least one `1.0.0-rc.N` is published and available for review, release artifacts/checksums are independently verified, the final compatibility approval is recorded on the exact final release commit, and no high/critical release blocker remains.
- Baseline packages remain usable but are outside the stable package promise unless separately promoted by evidence-backed maturity review.
- GitHub-host protections previously recorded as Blocked/manual remain limitations unless separately verified as configured.
