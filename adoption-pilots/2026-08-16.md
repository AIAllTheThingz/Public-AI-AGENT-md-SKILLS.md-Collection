## Cross-pilot findings

### What worked

- The published `generate-manifest` and `compose-agents` tools could be applied to three materially different real repositories.
- Package slugs, profile identities, operating-system selection, framework selection, and traceable source hashing worked without repository-author context.
- The toolchain correctly avoided inventing project-specific runtime, infrastructure, credential, deployment, or authorization facts.
- Project-specific `AGENTS.md` hierarchies were necessary and useful rather than optional ceremony.
- Failed commands exposed real environment/testing constraints that would have been hidden by repository-only examples.

### What needed correction

1. Windows PowerShell 5.1 estates needed an explicit evidence-bounded compatibility path. Fixed by #65 / #67.
2. Secondary profiles needed discipline-link expansion under `--include-profile-required`. Fixed by #66 / #68.
3. A traceable no-copy composition bundle is not automatically an instruction parent for downstream application files. All three final pilot instruction scopes now explicitly bind agents to the exact pinned upstream sources and applicable transitive standards; unavailable sources produce a `Blocked` adoption state.
4. Enterprise-PS-Scripts currently has no Pester test files. That remains a downstream project issue rather than an upstream standards defect.

## Maturity use

These pilots are representative downstream adoption evidence for the specific packages and profiles they exercised. They do not promote any package automatically.

For later maturity review:

- C#/.NET has real evidence from TheCertMaster and WindowsScriptRunner.
- PowerShell has real evidence from Enterprise-PS-Scripts and WindowsScriptRunner, with the legacy runtime boundary now clarified upstream.
- ASP.NET Core and the selected project profiles have downstream composition evidence from the two application-bearing pilots.
- Terraform/OpenTofu has package-level adoption tests from #47 but was not exercised by these three real downstream pilots, so this pilot set alone is insufficient for a Terraform/OpenTofu stable-maturity decision.

Stable promotion still requires the complete evidence set and independent specialist review defined by `MATURITY_POLICY.md`.
