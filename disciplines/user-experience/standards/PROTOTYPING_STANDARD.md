# Prototyping Standard

## Purpose

Use bounded prototypes to answer named questions without creating silent production commitments.

## Required behavior

- Define the hypothesis, audience, fidelity, scope, data, time boundary, success and stop criteria, and prohibited uses.
- Mark simulated behavior, missing controls, fake data, unsupported states, and accessibility limitations visibly.
- Do not expose prototypes as production, process sensitive data without authorization, or treat prototype code or technology as architecture of record.
- Require explicit review before carrying prototype decisions, code, dependencies, or data models into normal implementation.

## Required evidence

Prototype charter, assumptions tested, results, limitations, disposition decision, and links to changed requirements or ADRs.

## Completion gate

Prototype completion establishes only the documented learning; it does not establish product, architecture, security, accessibility, or production readiness.
